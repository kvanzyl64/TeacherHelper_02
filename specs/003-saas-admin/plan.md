# Implementation Plan: SaaS Admin

**Branch**: `003-saas-admin` | **Date**: 2026-09-26 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/003-saas-admin/spec.md`

## Summary

Create a dedicated SaaS-owner administration area that gives the platform owner a business-safe overview of centre health, subscription status, payment risk, and operational alerts across the multi-tenant product. The design keeps the existing centre workspace and tenant boundaries intact, adds a separate platform admin route family, and respects the constitution’s least-privilege and privacy rules by restricting read-only support access to summary data only.

## Technical Context

**Language/Version**: TypeScript 5.x with React and Next.js App Router 15.x

**Primary Dependencies**: Existing Next.js web app, role-aware route guards, centre dashboards, payment and oversight services, and the current multi-tenant domain model

**Storage**: Existing PostgreSQL-backed domain and integration services; this feature reuses tenant-aware billing, audit, and operational data rather than creating a second data store

**Testing**: Vitest for tenant and domain regression coverage; Playwright for admin route and permission validation; contract tests for admin permissions and route behaviour

**Target Platform**: Desktop and mobile browsers for platform owner and read-only support users

**Project Type**: Multi-tenant web application with a new platform-admin route family and reused domain services

**Performance Goals**: Admin overview pages should render quickly for a platform owner to spot healthy versus risky centres, with summary queries returning within the existing application responsiveness targets

**Constraints**: Preserve tenant isolation, least privilege, and privacy by default; do not expose child, guardian, or session details in the platform admin surface; limit read-only support access to summaries and alerts only

**Scale/Scope**: SaaS-level overview for all centres, billing risk summaries, operational alerts, and safe centre detail drill-downs without broadening into raw child or family data access

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Tenant isolation and least privilege**: PASS. The feature introduces a platform-level route family that is separate from the centre workspace and keeps data access narrowly scoped to approved admin roles.

- **Security and operational constraints**: PASS. The design reuses existing tenant-aware authorization and audit practices; no new uncontrolled access model is introduced.
- **Delivery and quality gates**: PASS. The plan includes validation through tests and build checks before release review.

No constitution violations or complexity exceptions are required.

**Structure Decision**: Keep the existing single web application and shared packages. Add the SaaS admin route family as a dedicated route group under the existing Next.js App Router and reuse the current domain, billing, and oversight services for summary logic. Avoid a separate frontend or a multi-app deployment for this feature.

## Phase 0: Research Decisions

- Keep the admin area separate from the centre workspace to preserve tenant isolation and business-role clarity.
- Use business-safe figures, not child-level details, in the platform overview and centre summaries.
- Limit support users to read-only admin access with explicit permission assignment in the first release.
- Distinguish billing, portfolio, and alert views as separate actions because they support different decisions and risk response paths.
- Record admin actions and escalation decisions in the existing audit/event model.

# Page Data and Authorization Contract

This contract maps every current data-bearing route to its PostgreSQL source and authorization boundary. The public landing page and generic error states are static and do not query tenant data. No data-bearing page may use production fixture arrays or in-memory repositories.

## Repository Contract

- All SQL runs server-side through a bounded pool and parameterized query APIs.
- Tenant repositories use a checked-out client and transaction-local `app.centre_id` / `app.user_id`; they never set session-wide tenant context on a pooled connection.
- Every tenant-owned table has RLS enabled and policies tested for both allowed and denied rows. Runtime roles are not table owners and do not have `BYPASSRLS`.
- Platform-admin repositories are distinct from tenant repositories and can return only reviewed business-safe views/DTOs. They do not obtain global access by changing centre context.
- Page DTOs contain only fields required by the visible screen. Browser components never receive database clients, secrets, auth tokens, or unrestricted records.
- Each row above must have at least one PostgreSQL integration test and one route-level or workflow test appropriate to the operation.
